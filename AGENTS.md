# Working in this repo

Conventions an agent (or a returning human) should follow when changing Cadence.

## Layering

```
src/core/  →  no DOM access, no imports from ui/ or app/
src/ui/    →  DOM rendering, imports from core/
src/app/   →  wires the two together
```

`core/` must stay runnable under `node --test` with no browser and no DOM shim. If a change to `core/` requires `document` or `window`, the logic belongs in `ui/` instead.

## The keystroke path is hot

`App.onKeyDown → Run.press → TypingStage.markChar` runs on every keypress, up to about 13 times a second at 130 WPM. In that path:

- Never re-render the passage. Toggle a class on the one character span that changed.
- Move the caret with `transform`, which the compositor can handle, not `left`/`top`, which forces layout.
- Do not allocate per keystroke where it can be avoided.

Anything expensive — corpus scanning, statistics, chart rendering — belongs between passages, not during one.

## Errors

Fallible functions return a result from `core/result.js`, they do not throw and do not return bare `null`:

```js
import { ok, fail } from './result.js';

if (candidates.length === 0) {
  return fail('selector.targeted', 'not-found', 'no quote contains these transitions', { targets });
}
return ok(quote);
```

Every failure names the `component`, a `failureType` from the union in `result.js`, and a `rootCause` specific enough to act on. Callers log with `formatFailure()` and, when the user is affected, surface it through `App.notify()`.

The exception is `Profile.load()`, which always returns a usable profile. A typing app that will not start is worse than one that starts empty.

## Measurement rules

Two invariants the statistics depend on. Both have already been violated once and produced plausible-looking but wrong numbers:

1. **Only correct keystrokes produce digraph samples.** After an error, the next keystroke is a recovery move; timing it as a transition makes everything look slow.
2. **Flight is keydown-to-keydown.** Keyup timing varies with how long a key is held, which is dwell, a separate measurement.

Also: a timestamp of `0` is valid. Use `null` for "not started", never `0`.

## Tests

```bash
npm test        # node --test test/core/*.test.js
```

`core/` changes need tests. Cover the failure path, not just the happy one — most of the bugs found while building this were in degenerate cases: an unreachable density threshold, an inline element with a percentage height, a CSS variable scoped to the wrong selector.

Name tests as behavioural claims (`'does not record a digraph across an error'`), not as method names.

## The quote corpus

`public/quotes/english.json` is generated by `npm run build:quotes` and **committed on purpose**, so production builds never depend on a network fetch. Do not gitignore it. Regenerate it only when you intend to pull upstream changes, and re-check the corpus size in the README if it moves.

`src/data/starter-quotes.js` is the small bundled fallback used when the fetch fails. It is not the main library.

## Adding a theme

Add a `[data-theme='name']` block in `src/styles/tokens.css` defining `--bg`, `--sub`, `--sub-alt`, `--text`, `--accent`, `--error`, `--error-extra`, then add the name to `THEMES` in `src/ui/theme.js`. Nothing else needs touching.

The per-finger palette (`--f-pinky` and friends) is deliberately theme-independent and lives on `:root`. It encodes anatomy, not mood, and it must resolve in both the hand guide and the stats charts.
